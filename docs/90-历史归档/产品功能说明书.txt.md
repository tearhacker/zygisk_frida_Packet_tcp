对，上一份已经**过时了**。它还是“Zygisk → Agent → PC MCP”的旧思路，而且把 Network/Packet 当成了相对独立的外围能力。

按照我们刚刚冻结的新架构，核心已经改成：

> **Zygisk 是进入目标 App 的启动入口，不是单独的分析工具；Runtime Plane 常驻 App 进程；Network Plane 与 Runtime Plane 双通道并行；PC/MCP 作为 Control Plane 在线控制；所有数据最终进入 Session + EventBus + Correlation。**

下面给你一份新的、可以直接作为项目正式《使用说明书》的版本。

# Android AI Dynamic Analysis Platform

## 用户使用说明书 v2.0

**文档状态：架构冻结版**

---

# 1. 产品定义

Android AI Dynamic Analysis Platform 是一套面向 Android APK/App 运行时分析的综合平台。

平台以：

* **Magisk / Zygisk**
* **Frida-Gum Runtime**
* **LSPlant / ART Runtime**
* **Native / Java Hook**
* **Memory Runtime**
* **Network Plane**
* **Packet / HEX**
* **EventBus**
* **Correlation Engine**
* **Session Manager**
* **MCP**
* **AI Agent**

组成完整分析体系。

产品的核心目标不是让用户分别操作 Frida、抓包工具、内存工具和 APK 分析工具，而是：

> **选择目标 App → App 正常运行 → Zygisk 自动进入 → Runtime 常驻 → PC/MCP 在线控制 → 实时 Hook / Memory / Network / Packet → AI 自动关联分析。**

# 4. 四大核心 Plane

## 4.1 Runtime Plane

Runtime Plane 位于目标 App 进程内部。

主要负责：

```text
Frida-Gum
LSPlant / ART
Java Hook
Native Hook
Module
Thread
Memory
Backtrace
Runtime Event
```

它是真正执行运行时分析的核心。

---

# 5. Zygisk 的定位

Zygisk 不再承担全部分析功能。

它的职责被严格限制为：

```text
识别目标 App
    ↓
进入目标进程
    ↓
加载 Runtime
    ↓
初始化 Runtime Bootstrap
    ↓
建立 Session 通道
```

也就是说：

> **Zygisk = Runtime 启动入口。**

而不是：

> Zygisk = 全部分析逻辑。

这样可以避免把整个系统逻辑堆积到 Zygisk Module 中。

---

# 6. Runtime Bootstrap

目标 App 启动以后：

```text
App Process
     ↓
Zygisk
     ↓
Package Match
     ↓
Runtime Bootstrap
     ↓
Frida-Gum
     ↓
ART Backend
     ↓
Memory / Module / Thread
     ↓
Runtime Ready
```

当 Runtime Ready 后，PC 端即可发现当前 Session。

用户无需手动 attach。


操作对象始终是：

# 81. 项目最终设计原则

### 原则一：App 是唯一主要分析对象

本项目当前冻结范围以：

> **Android APK / App 进程**

为核心。

不再把纯 ELF 后台 daemon / 独立二进制进程作为第一阶段目标。

---

### 原则二：Runtime 必须真正存在于运行中的 App

不是离线模拟。

不是单纯静态分析。

而是：

> **目标 App 正在运行时，Runtime 可以实时接受控制。**

---

### 原则三：Hook 必须实时生效

用户创建 Hook 后：

```text
当前 Session
 ↓
当前 App Process
 ↓
Runtime
 ↓
Hook
```

用于实时观察目标函数执行。

---

### 原则四：Network 与 Runtime 必须同时存在

不能只做：

```text
抓包
```

也不能只做：

```text
Frida Hook
```

而是：

```text
Runtime Plane
+
Network Plane
```

共同组成完整分析能力。

---

### 原则五：所有数据必须能够关联

最终目标：

```text
Packet
 ↓
Network
 ↓
Thread
 ↓
Java
 ↓
JNI
 ↓
Native
 ↓
Module
 ↓
Hook
```

尽可能形成完整调用链。

---

### 原则六：AI 是控制中心，而不是聊天窗口

AI 不只是回答：

```text
“这个函数是什么？”
```

而应该能够：

```text
查询
定位
Hook
读取
观察
抓包
分析
关联
建立 Rule
执行 Workflow
生成报告
```
