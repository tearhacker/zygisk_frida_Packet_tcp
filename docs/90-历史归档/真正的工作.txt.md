# 《Zygisk AI Runtime》源码供应链与工程目录 v1.0

## 一、最终只锁定 3 个外部核心源码

### ① Zygisk Module Sample

[topjohnwu/zygisk-module-sample](https://github.com/topjohnwu/zygisk-module-sample?utm_source=chatgpt.com)

**用途：**

```text
Zygisk API
模块入口
module.prop
Android.mk
Application.mk
zygisk.hpp
构建方式参考
```

它是**模板/API参考**，不是我们最终项目的业务代码。

官方 README 明确指出：

```text
module/jni/zygisk.hpp
```

是公开 Zygisk API 的 canonical header，并且 API 保持向后兼容。([GitHub][4])

---

### ② Frida-Gum

[frida/frida-gum](https://github.com/frida/frida-gum?utm_source=chatgpt.com)

**锁定版本：**

```text
17.18.0
```

官方 Release 页面目前列出的最新正式版本就是 17.18.0。([GitHub][2])

它是我们的：

```text
Native Runtime
       ↓
Interceptor
Stalker
Memory
Module
Thread
Backtrace
Memory Scan
Instruction / Relocator
```

核心底座。

**注意：不是把完整 Frida Desktop / frida-server 塞进 Zygisk。**

我们主要需要的是：

```text
Frida-Gum
```

也就是 C/C++ Runtime 层。

---

### ③ LSPlant

[LSPosed/LSPlant](https://github.com/LSPosed/LSPlant?utm_source=chatgpt.com)

**用途：**

```text
Java Method Hook
ART Hook
Method Deoptimization
ART Symbol Resolver
```

它与 Frida-Gum 的职责不同：

```text
Frida-Gum
    ↓
Native/C/C++层

LSPlant
    ↓
Java/ART层
```

LSPlant 官方目前声明支持 Android 5–17，包含 arm64-v8a、armeabi-v7a、x86、x86-64、riscv64。([GitHub][3])

# 三、这里最重要：源码到底放哪里？

## Zygisk

不要：

```text
third_party/zygisk-module-sample/
```

作为长期核心依赖。

我们只抽取需要的：

```text
zygisk/
├── zygisk.hpp
├── module.cpp
├── entry.cpp
└── bootstrap.cpp
```

其中：

```text
zygisk.hpp
```

来源于官方 sample。

官方 sample 的 C++ 代码位于 `module/jni`，构建产物最终进入 `module/zygisk/<ABI>.so`。([GitHub][4])

# 四、Frida-Gum 怎么放

这里不要把：

```text
frida/
frida-core/
frida-tools/
frida-python/
frida-node/
```

全部拉进来。

核心只考虑：

```text
third_party/
└── frida-gum/
    └── 17.18.0/
```

然后我们的 Runtime：

```text
runtime/
└── backend/
    └── gum/
```

负责封装它。

也就是：

```text
                    YOUR RUNTIME
                         │
                         ▼
                ┌─────────────────┐
                │ GumBackend      │
                └────────┬────────┘
                         │
                         ▼
                ┌─────────────────┐
                │ Frida-Gum       │
                │ 17.18.0         │
                └─────────────────┘
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     Interceptor      Memory         Module
```

这样以后即使 Gum 升级：

```text
17.18.0
   ↓
17.19.x
```

也只需要替换 Backend/third_party，而不是把整个项目推倒重来。

```text

```



## 十二、一个关键的现实调整

还有一点我要纠正之前文档里的表述：

**Frida-Gum 17.18.0 可以作为核心 Native Backend，但不能简单理解为“下载源码就直接能嵌入 Android Zygisk”。**

官方 Frida-Gum 仓库说明，给自己项目进行静态链接时可以使用 **devkit**；完整源码仓库则是 Gum 的开发源码。([GitHub][5])

所以实际落地时应该进一步决定：

```text
方案 A
Frida-Gum devkit
        ↓
你的 Runtime
```

还是：

```text
方案 B
Frida-Gum source
        ↓
Android 构建
        ↓
你的 Runtime
```

**这一步不要盲目把整个 Frida-Gum 源码复制进去。**
