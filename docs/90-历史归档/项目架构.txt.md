# 5. Frida 集成原则

Frida 在本项目中属于：

> **底层 instrumentation backend。**

平台自己的 API 不暴露 Frida 原始 API。

例如 AI 不直接使用：

```text
gum_interceptor_attach()
```

而使用：

```text
runtime.hook()
```

平台内部：

```text
runtime.hook()
      ↓
Hook Engine
      ↓
Native Backend
      ↓
Frida-Gum
```

这样以后即使替换：

```text
Frida-Gum
ShadowHook
ByteHook
其他 Backend
```

上层 API 不需要变化。

# 10. Memory 安全模型

Memory Write 必须受到 Session 和权限控制。

至少检查：

```text
session_id
process_id
address
mapping
permissions
size
```

禁止 Runtime Service 因一个错误地址直接导致整个 Analyzer 崩溃。

原则：

```text
Invalid Address
     ↓
Validation
     ↓
Reject
     ↓
Error Event
```

而不是：

```text
Invalid Address
     ↓
Analyzer Crash
```

# 23. HTTPS 架构

HTTPS 必须明确：

> **TCP 抓到 ≠ HTTPS 明文可修改。**

HTTPS 要实现：

```text
HTTPS
 ↓
TLS interception capability
 ↓
HTTP layer
 ↓
Modify
 ↓
Forward
```

前提是测试环境允许建立相应的 TLS 拦截条件。

例如应用存在：

```text
certificate validation

```

时，网络层不一定能够直接获得 HTTP 明文。

因此 Network Engine 必须允许多个 Backend：

```text

```

```text

HTTPRequest
HTTPResponse
Packet
```

# 62. 最终一句话定义

本项目正式定义为：

> **Zygisk 负责自动进入目标 APK 进程；Frida-Gum + LSPlant 负责真实 Runtime Instrumentation；Memory/Hook 必须实时生效；Network Engine 负责实时网络观察与可插拔拦截；Packet Engine 负责真实数据对象、HEX、修改与重放；Event Bus + Correlation Engine 把 Runtime 与 Network 统一起来；MCP 把整个 AnalysisSession 暴露给 AI。**

最终用户体验：

```text
选择 APK
   ↓
启动
   ↓
Zygisk 自动注入
   ↓
Runtime 自动启动
   ↓
Frida-Gum / LSPlant Ready
   ↓
Network Ready
   ↓
Session Ready
   ↓
AI / MCP 接管
   ↓
实时观察
   ↓
实时 Hook
   ↓
实时改值
   ↓
实时拦截
   ↓
实时修改数据
   ↓
继续执行
   ↓
自动关联调用链
   ↓
AI 分析
```

这才是本项目 v1.0 的最终工程闭环。

这版相对于之前的冻结文档，**真正增加的核心不是“功能列表”，而是把“实时控制面”正式写进了架构**：`runtime.hook / memory.write / network.intercept / packet.modify / forward / drop` 都必须落到实际执行链路，而不是模拟层。

下一步就不应该继续改架构了。应该进入**源码供应链锁定 → 仓库版本锁定 → Android NDK/CMake 工程骨架 → Zygisk `libai_analyzer.so` 最小可运行版 → Frida-Gum 真正嵌入 → 第一个 Native Hook 实测 → Memory Write 实测 → Network Intercept 实测**。之前那份源码供应链文档可以直接作为依赖基线；其中已经把 Magisk、Zygisk sample、Frida-Gum、LSPlant、JADX、Apktool、PCAPdroid、mitmproxy、MCP SDK 等分层锁定。
